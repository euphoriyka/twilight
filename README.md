# TWILIGHT — сайт компьютерного клуба (Django + PostgreSQL)

Главная страница (3D-сцена, игры, тарифы, карта зала, калькулятор), личный кабинет клиента `/account/`
и админ-панель `/admin-panel/`. Данные хранятся в PostgreSQL по схеме из `DB_computer_club_physic_model.xlsx`.

## Запуск

1. Python 3.11+ и PostgreSQL 14+. Создайте базу и пользователя:
   ```sql
   CREATE USER twilight_user WITH PASSWORD 'ваш-пароль';
   CREATE DATABASE twilight OWNER twilight_user;
   ```
   (расширение `btree_gist` включается миграцией; в PostgreSQL 13+ это доступно владельцу базы,
   в более старых версиях выполните `CREATE EXTENSION btree_gist;` под суперпользователем.)
2. Окружение и зависимости:
   ```bash
   python -m venv .venv
   source .venv/bin/activate          # Windows: .venv\Scripts\activate
   pip install -r requirements.txt
   cp .env.example .env               # впишите пароль БД и свой DJANGO_SECRET_KEY
   ```
3. Миграции (в архиве есть только `club/migrations/0001_btree_gist.py`, остальные создаёт Django):
   ```bash
   python manage.py makemigrations accounts club
   python manage.py migrate
   ```
4. Демо-данные и запуск:
   ```bash
   python manage.py seed_demo_data
   python manage.py runserver
   ```
   Открыть: http://127.0.0.1:8000/

Демо-вход (пароль у всех `Twilight#2026`, только для демонстрации):
- администратор: `admin@demo.twilight.test`
- клиенты: `alexey@demo.twilight.test`, `maria@demo.twilight.test`, `igor@demo.twilight.test`, `daria@demo.twilight.test`

Пересоздать демо-историю: `python manage.py seed_demo_data --reset --yes`.
Тесты (нужен PostgreSQL): `python manage.py test`.
Свой администратор: `python manage.py createsuperuser` (роль `admin` проставится сама).

## Как реализована схема БД

Таблицы `users`, `computers`, `tariffs`, `bookings`, `sessions`, `payments` — с теми же полями, типами,
`UNIQUE`, `CHECK`, `DEFAULT` и индексами, что в xlsx. Модель сессии называется `GameSession`
(`db_table = "sessions"`), чтобы не путать с сессиями Django. Колонка `password` хранится как `password_hash`
(хэш Django), поле `last_login` не создаётся.

**Добавлено сверх xlsx (минимально, нужно для сайта):**
- `computers.category` и `tariffs.category` — Standard / Premium / VIP (на сайте три категории, в xlsx их нет);
- `tariffs.kind` — `hour` или `night` (ночной тариф действует 23:00–08:00).

**Добавлено как защита (ограничения, не колонки):**
- `bookings`: `EXCLUDE` — PostgreSQL не даёт создать два активных (`pending`/`confirmed`) бронирования одного
  компьютера с пересекающимся временем, даже если две заявки придут одновременно;
- `sessions`: не больше одной активной сессии на компьютер;
- `payments`: у сессии не больше одного платежа в статусе `pending`/`paid` (защита от двойного нажатия).

## Бизнес-правила

- Время округляется вверх до полного часа, минимум 1 час. Итог сессии фиксируется при её завершении
  (`sessions.total_amount`), поэтому изменение цены не меняет историю.
- Бронь: от 1 до 12 часов, не в прошлом, не дальше чем на 30 дней вперёд, не на обслуживаемый компьютер.
- Клиент может отменить только свою ещё не начавшуюся бронь. Сессию по брони можно начать только
  по подтверждённой броне, начиная с -15 минут до её старта.
- Оплата демонстрационная: номера транзакций вида `DEMO-XXXXXXXXXXXX`, реального эквайринга нет.
- Тарифы и компьютеры не удаляются (только отключение / статус «Обслуживание»), чтобы сохранилась история.

## Отличия от прежней версии сайта (v5)

- Тарифы, цены, места и их занятость берутся из БД; стоимость в калькуляторе считает сервер (`/api/quote/`).
- «Пакет 10 ч» убран: в схеме `tariffs` есть только цена за час. Ночной тариф теперь почасовой
  (110 / 165 / 255 ₽/ч) вместо фиксированных 990 / 1490 / 2290 ₽ — это демо-значения.
- Карта зала: 24 места (12 Standard, 8 Premium, 4 VIP) вместо 36 демонстрационных.
- Цифровая карта участника привязана к аккаунту (раньше хранилась в браузере).
- Форма бронирования сохраняет заявку в БД (нужен вход клиента).
- Добавлен курсор-звезда (`static/js/cursor-star.js`): отключён на сенсорных устройствах, при
  `prefers-reduced-motion` без шлейфа и инерции, в админ-панели без шлейфа.
- Избранные игры, достижения, режимы оформления и музыка по-прежнему хранятся в браузере (localStorage).

## Безопасность

CSRF-защита на всех POST-формах; пароли только в виде хэша; роль нельзя выбрать при регистрации;
права проверяются на сервере в каждом представлении; секреты — в `.env` (он в `.gitignore`);
при `DJANGO_DEBUG=0` включаются secure-cookie и обязателен `DJANGO_SECRET_KEY`.
